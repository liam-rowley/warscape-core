# Decisions

One line per decision: date, who, the decision, and whether it is reversible. **Append only**; a reversal is a new dated line that
names the one it replaces. Detail lives in the doc or code that owns the topic. Numbers are `C<n>` so they never collide with a game
repo's `D<n>`. Lines marked "proposed" came in a pull request; Liam's merge of that pull request accepts them.

| C1 | 2026-10-28 | Liam | The core holds the game-agnostic machinery (`napoleon-remastered` `docs/plans/PLAN.md` section 4; its D10, D18); game repos pin a released version and never patch it in place. Empire is not modified until it moves onto the core. | no |
| C2 | 2026-10-28 | Liam | Python 3.12, standard library only, so CI and a fresh clone need no installs. | yes |

| C6 | 2026-10-28 | proposed (Claude, PR 1) | The pre-push hook runs the fast gates on every push to any branch (Empire's checked main only); bypass is `git push --no-verify` with a reason in the commit. | yes |
| C7 | 2026-10-28 | proposed (Claude, PR 1) | Registry JSONL merges by union (`.gitattributes`); a union that keeps two versions of a row fails `wsc reg check` (duplicate id) until fixed. | yes |

| C9 | 2026-10-28 | Liam (review in the napoleon planning chat) | Tool retirement warnings are off by default (`[tools] retire_after_days = 0`) until the job queue (napoleon D16) stamps `last_used` when a job report cites a tool; a field nobody updates would make every tool warn at once. A registry reference (`x-ref`) to a registry the repo does not declare fails only when a row fills that field. | yes |
| C10 | 2026-10-29 | proposed (Claude, napoleon J5) | `core_pin` checks the tag (B5): a game's pin is `vX.Y.Z` (lower-case v) and must be a tag on the core checkout's HEAD whenever the checkout has tags (a shallow CI submodule has none, so VERSION alone is compared there); inside the core, every tag on HEAD is `v` + `VERSION`. The existing tag `V0.1.0` breaks this: the next release is tagged lower-case. | yes |
| C11 | 2026-10-29 | proposed (Claude, napoleon J5) | New `hooks` gate (warning, skipped when `CI` is set): the pre-push hook is wired (`core.hooksPath`) in this clone, so "set the hook once per clone" is checked instead of remembered. | yes |
| C12 | 2026-10-29 | proposed (Claude, napoleon J5) | Every git subprocess the core runs drops the repository-selecting `GIT_*` variables git exports to hooks (`warscape/repo.py` `git_env`): in a worktree the pre-push hook's `GIT_DIR` made `core_pin` read the game's index and refuse the push. | yes |
| C13 | 2026-10-31 | proposed (Claude, napoleon J12), accepted by Liam's merge | **Pillow on the PC side only.** C2 (standard library only) stays the rule for `warscape/`, the gates and the host tests. | C14 | 2026-10-31 | proposed (Claude, napoleon J12), accepted by Liam's merge | **The proxy, the harness and the save tools live here** (phase 1 promotion): `proxy/src` (the DLL core), `proxy/tests`, `proxy/tools`, `harness/`, `saves/`. A tool finds the game through `proxy/tools/layout.py` (the superproject that pins this repo, `wsc.toml` `[proxy]`/`[harness] adapter`, else the one adapter in the repo), never by its own location or a game name; `tests/test_moved_tools.py` lints the moved trees for game names. CI builds and tests them against the null game (`proxy/tests/null_game`). | yes |
| C15 | 2026-11-01 | proposed (Claude, napoleon J55) | **Registry storage and views are a repo's choice, opt-in** (`wsc.toml` `[storage] dir`, `[views] commit`): a registry may keep one canonical file per row (`<name>/<id_to_file(id)>.json`, indented, name derived from the id by a reversible Windows-safe percent-encoding and checked against it), and views may be written to a git-ignored folder and checked only for rendering. Declared by the repo, not the schema, because one game's merge pattern is not a property of a core schema (B2 is unbuilt). Defaults keep the 0.5.0 layout byte for byte. | yes |
