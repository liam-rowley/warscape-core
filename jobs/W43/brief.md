## Goal

Measured 2026-11-05: renumbering and re-merging them cost about 2 h of sessions across napoleon J80 and core W34, W39, W40 and W31, and three plan pull requests that each passed alone took `docs/BACKLOG.md` over the doc cap and turned `main` red (issues #122, #123; #124 split the file). ## Decisions already made (follow them; a deviation goes in the report with its reason)
1. **File layout: one dir-storage registry through the existing machinery.** `registries/decisions/<id>.json`, schema `schemas/decisions.schema.json`, declared as `core:decisions`, in `[storage] dir`. Fields: `id`, `date`, `who`, `decision`, `reversible` (a string, as the old rows carry text), `replaces` (optional array, `x-ref` decisions). So `wsc reg`, `wsc find` and `reg check` work with no new storage code.
2. **The id rule: a non-sequential id, minted, never counted.** New ids are `<prefix><yymmdd>-<4 lower-case hex>`, for example `C261105-a3f2`, from `wsc reg add decisions --mint key=value ...` (date from the clock, hex random, checked against the rows on disk). Why not an id allocated at merge: `main` takes no direct commits, so a merge-time number needs a bot commit after every squash, and the row a reviewer read would change after review. Why not a reserved ref (the `claims` model): it needs the network and a check that a row's number was really reserved. A random id needs neither, and two branches that still draw the same one meet as an add/add on one path, which git refuses rather than merges. **Existing ids stay valid:** `C1`-`C39` keep their numbers, and a schema pattern accepts both forms, so reports and reviews still resolve. Numbers are closed: a new numeric decision id is refused.
3. **`[policy] decisions` carries over with one new value form.** `decisions = "registry:decisions"` names a registry; any other value stays a Markdown path and takes today's code unchanged (the default for every consumer). `repo.py` checks that the named registry is declared and in `[storage] dir`.
4. **Append only, as a file rule, on every branch kind, in `policy.py`:** under the decisions folder a path that exists on the base and is changed, deleted or renamed is refused with the Markdown rule's message (a reversal is a new row, with `replaces` naming the old one). So rows are immutable: stronger than a replacing row being allowed to edit, and the same as today. An added file must parse, its `id` must equal its file name and be the minted form with the prefix, `date` must be YYYY-MM-DD, `who` and `decision` non-empty, `reversible` `yes` or `no`, and each `replaces` a row at the head. Unparsable fails closed. **The "merge the base" error goes away:** `changed` is taken from the merge base, so a branch behind the base no longer touches another branch's rows. `added_decision_rows` keeps returning `{id, text}`, `text` being the `| id | date | who | decision | reversible |` line, so rule F and game modules read it unchanged.
5. **Backlog rows become job rows (Liam, 2026-11-05).** A new job status `later` in `schemas/jobs.schema.json`: recorded and searchable, ignored by `wsc jobs next`, `jobs review` and any autopilot start, promoted by setting it to `needs_brief`; shown by `jobs view`, checked by `jobs check`, with no `semver` or brief required. New optional field `backlog_id` keeps the old number, and `wsc find B96` resolves it (a strong search field), so citations in job files keep working; old reports and reviews are not rewritten. Docs say `later` rows are picked up batched by area, not one job each. Job ids stay sequential `W<n>`: the row's id rule is about decisions.
6. **`plan_doc` stays a free-text key.** The core's value becomes prose naming the `later` rows and `wsc find`. The default is unchanged.
7. **`doc_size` needs no code:** decision rows and job rows are JSON, not living docs, and views are not committed, so no plan branch can take a table over the cap. Add a host test that shows it.
8. **Views (J55, C19): rendered, not committed.** `python3 wsc.py reg render` writes `_scratch/registries/decisions.md`. Decisions sort by date then natural id; add a natural sort in `render` rather than a second code path, and let a registry opt out of `_cell`'s 200-character cut (a decision is longer than that, and the view is how it is read).
9. **The importer extends `reg migrate`:** `wsc reg migrate decisions --from-md FILE [--check]`, columns from the schema's `x-view`. `--check` compares every table row of FILE with the row files by field value and exits 1 naming each row that differs or is missing.
10. **`docs/DECISIONS.md` cannot be deleted on this branch, and that is the shape of the migration, for the core and for a game.** The job is judged with the base's rules (C24), and on the base `decisions_problems` refuses a head without the rows. So a migration is two pull requests: (a) this job adds the rows, flips the config and leaves every row line of the Markdown file byte-identical (its prose header may change: only row lines are compared, so it says the file is frozen and points at the registry); (b) after merge, a `meta/` branch deletes the file and the key below.
11. **The window between (a) and (b) is guarded by code.** New key `[policy] decisions_retired = ""` (the core: `"docs/DECISIONS.md"`): while that file exists, the `registries` gate runs the `--check` comparison, so a stale branch that adds a Markdown row fails instead of its row vanishing. `gate_doc_paths` skips the retired file; `skips` finds a decision id through the row files in registry mode.
12. **This job's own decision is a minted row file** naming W43 (rule F's wording), not a `C40` line: the Markdown table is frozen from this branch on.

13. **`registries/tools.jsonl` moves to one file per row too (Liam, 2026-11-05, relayed by the napoleon session).** It changed 19 times since 2026-11-03, and on W31 a merge auto-merged it with no conflict but left duplicate ids (`wsc.jobs`, `wsc.policy`), turning the `registries` and `tools` gates red. Use the mechanism napoleon uses (`[storage] dir = ["jobs", "tools", "engine_facts"]`): `python3 wsc.py reg migrate tools --to dir`, no second one. Keep all 91 rows. No other registry changes storage. The `[policy] meta` globs gain `registries/tools/*`, and `CLAUDE.md` :32 names the new folder.

14. **The backlog rows cannot move on this branch either.** `policy.py` refuses a job branch that changes any row but its own (`other_rows_changed`), under the base's rules (C24), and `later` is not in the base's schema. So this job builds the status and a host-tested importer, `wsc jobs later --from-md FILE... [--area name] [--check]`: one `later` row per table row, the next free `W<n>`, `backlog_id` the old number, title the bold lead, description holding every cell with no text lost (the `area` goes in the row; B19 and B98 hold unescaped pipes: split from the outer cells, and state how). After merge a `plan/` branch runs it on the two files, re-counts at that merge (64 when this was written; W42 removes B99), runs `--check`, and deletes both files: `registries/jobs/*` and `docs/*` are in the `plan` globs. This job leaves both files in place. The report gives the exact commands.
