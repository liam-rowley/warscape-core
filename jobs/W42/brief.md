## What exists (read before building; checked 2026-11-05 against `origin/main` 0444376)
- **The workflow:** `ci/gates.yml.in` renders `.github/workflows/gates.yml` (`python3 wsc.py ci render`; the `ci_render` gate compares them). `gates` is a matrix over `os: [ubuntu-latest, windows-latest]`, `timeout-minutes: 10`, no `needs`, no `if`.
- **The trap in (2):** the `matrix` context is not available in a job-level `if:`, so one leg cannot be skipped by `if:`. A matrix job skipped as a whole is expected to report one unexpanded check (`gates`), and a leg removed from a dynamic matrix reports nothing, so either way `gates (windows-latest)` would never report and every docs-only pull request would wait for it for ever. That is expected behaviour, not measured here: step 2 measures it. Skipped plain jobs do report under their name (`proxy`, `harness-windows` in run 42111361880: `skipped`, and they count as passed).
- **The machinery to reuse:** `warscape/ci_render.py` `block_changes`, `block_if`, `block_pass_marker` are generic over `[ci] inputs`: a new input set gets its `changes` outputs, its pass marker and its fail-safe `if:` with no new render code. `warscape/ci.py` `classify` (files None, an unknown base, means everything changed), `required_jobs` (by check name), `GREEN` (`skipped` counts).
- **Required checks:** `wsc.toml` `[ci] required_checks`; the Main ruleset (id 26071159) requires `gates (ubuntu-latest)`, `gates (windows-latest)`, `policy`, `proxy`, `harness-windows` by name, not strict. `warscape/ci_settings.py` `workflow_jobs` reads a job's plain `name:`, `produced` matches on it, so plain jobs named as the two checks need no ruleset change.
- **B99:** `proxy/tools/netfetch.py` `ci_cache` (:86) hashes `pins.read_bytes()`. `proxy/tools/fetch_ui.py` reads only `KEYS` (`rmlui`, `freetype`, `lua`, `stb_image`, `stb_image_write`), and of those only `repo`, `commit`, `url`, `sha256`. Napoleon's `viewer/pins.json` also holds `emsdk_image` and, since J80, `playwright`. `tests/test_netfetch.py` `test_ci_cache_prints_a_pin_key_and_the_raw_download_paths` (:321) asserts a trailing newline changes the key: that assertion inverts here. The row is `docs/BACKLOG.md` B99 (:49).
- **A game:** napoleon's `gates` job is one plain ubuntu job, `required_checks = ["gates", ...]`: change (2) has nothing to do there.

## Decisions already made (follow them; a deviation goes in the report with its reason)
1. **Two plain jobs replace the matrix, unless the probe contradicts it:** `gates` with `name: gates (ubuntu-latest)` (no `needs`, so it starts at once) and `gates-windows` with `name: gates (windows-latest)`, `needs: changes`, `{{wsc if gates_windows}}`, and `{{wsc pass_marker gates_windows shell=bash}}` as its last steps. Both `timeout-minutes: 20`. The check names, `required_checks` and the ruleset stay as they are. Add `gates-windows` to the `notify` `needs=`.
2. **The fallback, if a skipped plain job does not satisfy the check by name:** keep the matrix, give the job `needs: changes` and `if: ${{ !cancelled() }}`, and put the same condition on each step behind a `matrix.os` test, so the leg starts, does nothing and reports green. Slower by a runner start, and it must not report green when `changes` failed.
3. **The input set is a new `[ci] inputs` key, `gates_windows`, matching everything but paperwork:** `'^(?!docs/|jobs/|registries/jobs/|README\.md$|CLAUDE\.md$)'`. That is the `[policy] plan` set, widened from briefs to the whole job folder, so `plan/` and `brief/` branches and the report and review commits all skip. Why not `docs/` alone: most queue traffic is a brief plus its row, and Python reads those the same on both systems; the `windows_paths` gate still runs on ubuntu. The row's "docs" means this set; say so in the report.
4. **The pass marker stays on**, as for `proxy`: a push to `main` has no diff base, so every set counts as changed there, and the marker is what lets a paperwork merge skip Windows on `main`. A code merge still runs it, and that is the backstop for what a branch skipped.
5. **B99 hashes the fields the fetchers read:** for each key of `fetch_ui.KEYS`, in order, the entry's `repo`, `commit`, `url`, `sha256` as canonical JSON (`sort_keys=True`), with an absent key or field written as absent, never dropped. `_doc`, `why`, `licence`, `version`, `tag` and unknown top-level keys do not move the key. **Fail safe:** a pin file that is missing keeps today's `no ui pin file` line; one that does not parse hashes its bytes, so the key still moves and the fetcher reports the fault. Bump the `netfetch 1` prefix to `netfetch 2`. `fetch_lua.PIN` and `fetch_dxvk.PIN` stay as they are. If a fetcher turns out to read another field, add it and say so.
6. **A learning becomes code:** `ci_settings.findings` reports a problem for a matrix job with a job-level `if:` whose checks are required, naming the fix (two plain jobs), if the probe shows the check goes missing. If the probe shows it does not, skip this and report it.
